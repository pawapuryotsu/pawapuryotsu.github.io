# パワプロアプリ攻略ベース（公開用サイト）

公開先は GitHub Pages（main ブランチの /docs フォルダ）。

## しくみ
- `src/` … 元の部品（`layout.html`＝ヘッダー・フッター共通、`pages/*.html`＝各ページの本文、`decks.js`＝デッキのデータ、`assets/`、`img/decks/`）
- `build.py` … `src/` から公開用の `docs/` を作る。`python3 build.py <chars.json>`
- `docs/` … 公開されるファイル（自動で作るので手で直さない）

## よく変える設定（build.py の上のほう）
- `SITE_URL` / `CUSTOM_DOMAIN` … 独自ドメインにしたら変える
- `ADSENSE_CLIENT` … AdSense の `ca-pub-…`。入れると全ページに審査用コードと `ads.txt` が入る
- `AD_SLOT` … 広告ユニットの番号。入れるとトップ（ツールの下）とデッキページ（一覧の下）に広告枠が出る
- `CONTACT_FORM` … Googleフォームの URL

## デッキを追加するとき
`src/decks.js` に1件足し、画像（jpg）を `src/img/decks/` に置いて `build.py` を実行。
キャラを追加したら pawa-data の `chars.json` を使って `build.py` を実行し直す（`docs/data/chars.json` が更新される）。

## デッキページのレイアウト規則（新しいデッキを足すときもこれに合わせる）
デッキの追加手順は上の「デッキを追加するとき」。見た目は次のルールで統一しているので、画像を作る・データを書くときに守る。

**画像（src/img/decks/ に jpg で置く。選手名・ゲーム内の名前は必ず除く）**
- 育成結果 `r`：484×104。表示はどのデッキも同じ大きさ（`.top img` で幅 min(242px, 画面幅−165px)。無課金タグの有無で変えない）。ランクアイコン＋ポジション帯＋総経験点だけ。黄色の縁取りは付けない（アンドロメダ学園と同じサイズ・見た目）。
- メインデッキ `d`：6人分を横一列。名前は入れない。
- サポートデッキ `s`：3人分。表示幅は CSS で「メインデッキの0.517倍」に固定してあり、1キャラのアイコンがメインと同じ大きさになる（ゲーム画面ではサポートのアイコンが約1.13倍大きいため）（`.subdeck`）。切り抜きはメイン画像と同じ縮尺で、横幅は約385pxを目安にする。
- 育成した選手の能力 `a`（任意）：選手の能力画面（投手能力データ／野手能力データ）のスクショから、能力が並ぶ帯だけを切り抜く。幅750pxの画面なら (26,410)〜(713,630)（左右・上下の水色の縁は残す）。投手は球速・コントロール・スタミナ＋変化球の図、野手は弾道〜捕球の7項目。選手名・高校名・特殊能力の欄は入れない。ページでは「育成のポイント」と「解説動画」の間に幅いっぱい（最大520px）で表示。`a` が無いデッキは何も表示しない。
- 基礎上限 `u`：投手デッキは球速・コントロール・スタミナの3種だけを切り抜く（`.baseimg.half`で半分の幅で表示）。野手デッキは6種。

**表の表記（投手デッキ＝roman。deck.js が自動で行うので decks.js には略称を書かない）**
- 得意練習は略称：球速＝球、コントロール＝コン、スタミナ＝スタ、変化球＝変、守備＝守、メンタル＝メン。
- 「タッグボーナス」は「タッグ」と表示する（横スクロールなしで練習効果とタッグが見えるようにするため）。
- サポートデッキの表に「基礎上限」欄。球速・コン・スタの3種だけを「コン+8」の形で表示し、複数あれば2行。ミート・パワー・走力・肩力・守備力・捕球は表示しない。
- 野手デッキ（andromeda）も「基礎上限」欄あり。ミート・パワー・走力・肩力・守備力・捕球の6種だけを「ミート+3」の形で表示し、複数あれば2行。球速・コン・スタは表示しない。

**キャラ名（表）**
- フルネームで表示。[二つ名]は小さめの灰色文字で1行目に固定（折り返さない、CSS の .nick）、姓名は2行目。姓名が長いときは姓と名の間・「・」の後でだけ折り返す（deck.js の nameHtml、CSS は word-break:keep-all）。
- 例外として短く出すキャラは deck.js の SHORT_NAME に書く（エイル・オーウェン→「エイル」）。検索はフルネームでも一致する。

**備考欄（メイン・サポート両方の表の一番右。deck.js の NOTE_RULES で自動表示）**
- サポートデッキの表には「守備（ポジション）」欄は置かない（一致・不一致・回復の判定と意味が被るため）。
- 練習改革：そのLvで改革を持っているキャラに「〇〇改革」。複数人いても全員。投手デッキはコン改革・スタ改革だけ、野手デッキは筋力改革・走塁改革だけ表示（chars.json の bonus「〇〇練習改革(…)」で判定）。メイン・サポート両方。
- 経験点上限：サポートデッキで「サポ：獲得経験点上限」が一番高いキャラだけ、2行で「経験点上限／数値」。サポートのみ。
- 当てはまらなければ空欄。ルールを増やすときは NOTE_RULES に関数を足す。

**デッキのデータ（decks.js）**
- 無課金アカウントで育成したデッキには `f2p:true` を付ける。育成結果画像の右に「無課金」タグが出て、絞り込みの「無課金のみ」で表示できる。
- 並び順の初期設定は「選手ランクが高い順」（同じランクは総経験点が高い順）。選択肢は上から ランク順・総経験点順・育成日が新しい順。
- 各デッキに育成日（更新日）を `date:"2026-10-04"` の形で必ず書く。解説動画の下に表示され、並び順「育成日が新しい順」に使う。
- 育成のポイントは `tips`（箇条書き）、動画は `video`（YouTubeのID。動画が無いデッキは `video:"なし"` で「なし」と表示）。動画に注記が必要なときは `videoNote`（「※」は自動で付く）。
- 高校キャラ（chars.json の「所属高校」がそのシナリオの学校）には名前の後ろに●が付く。ロマン開花學園はメイン・サポート両方、アンドロメダ学園はメインだけ（deck.js の SCHOOL_MARK）。
- キャラ検索は、名前・読み仮名・二つ名の読み仮名のどれでも一致する（chars.json の「読み」「二つ名読み」）。
- 公開用リポジトリでは、コミット作者を noreply にし、コミット文・PR・サイトに本名や呼び名を書かない（公開名は「りょーつー」）。
