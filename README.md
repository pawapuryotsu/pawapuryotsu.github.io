# パワプロアプリ攻略ベース（公開用サイト）

公開先は GitHub Pages（main ブランチの /docs フォルダ）。

## しくみ
- `src/` … 元の部品（`layout.html`＝ヘッダー・フッター共通、`pages/*.html`＝各ページの本文、`decks.js`＝デッキのデータ、`assets/`、`img/decks/`）
- `build.py` … `src/` から公開用の `docs/` を作る。`python3 build.py <chars.json>`
- `docs/` … 公開されるファイル（自動で作るので手で直さない）

## よく変える設定（build.py の上のほう）
- `SITE_URL` / `CUSTOM_DOMAIN` … 独自ドメインにしたら変える
- `ADSENSE_CLIENT` … AdSense の `ca-pub-…`。入れると全ページに審査用コードと `ads.txt` が入る
- `AD_SLOT` … 広告ユニットの番号。入れるとトップ（ツールの下）とデッキページ（一覧の下）に広告枠が出る
- `CONTACT_FORM` … Googleフォームの URL

## デッキを追加するとき
`src/decks.js` に1件足し、画像（jpg）を `src/img/decks/` に置いて `build.py` を実行。
キャラを追加したら pawa-data の `chars.json` を使って `build.py` を実行し直す（`docs/data/chars.json` が更新される）。

**表の表記（投手デッキ＝roman。deck.js が自動で行うので decks.js には略称を書かない）**

- 「タッグボーナス」は「タッグ」と表示する（横スクロールなしで練習効果とタッグが見えるようにするため）。

- 野手デッキ（andromeda）も「基礎上限」欄あり。ミート・パワー・走力・肩力・守備力・捕球の6種だけを「ミート+3」の形で表示し、複数あれば2行。球速・コン・スタは表示しない。
- 野手デッキ（andromeda）のメイン表には Lv とコツボナの間に「セル」欄がある（サポート表には無い）。中身はメインデッキ画像のアイコン下の文字（敏捷・技術・精神・筋力・強化マス・タッグなど）を読んで、decks.js の main の各行に `{cell:"敏捷"}` と書く。最大4文字（強化マス）で、欄の幅は中身に合わせる。

**キャラ名（表）**
- フルネームで表示。[二つ名]は小さめの灰色文字で1行目に固定（折り返さない、CSS の .nick）、姓名は2行目。姓名が長いときは姓と名の間・「・」の後でだけ折り返す（deck.js の nameHtml、CSS は word-break:keep-all）。
- 横文字の名前（chars.json で名前欄が空、カタカナ）は最初の「・」「=」より後ろを表示しない（例：エイル・オーウェン→エイル、オーランド・ディクソン→オーランド、リムル=テンペスト→リムル）。漢字が入る名前（七井=アレフト、男・矢部明雄）はそのまま。deck.js の shortForeign。検索はフルネームでも一致する。

**PC表示（横幅720px以上。style.css の末尾 @media (min-width:720px)。全学園ページ共通で、新しい学園ページにも自動でかかる）**
- スマホ表示（720px未満）は上の規則のまま変えない。
- 720px未満でも、キャラ・備考以外の欄は中身の幅だけ取る（PCでウィンドウを狭めたときなど、余った幅は備考欄へ。セル欄や得意練習欄が広がらない）。
- 二つ名と名前を1行で表示（折り返さない）。見出し（練習効果・基礎上限など）も1行。
- 備考以外の欄（キャラ・Lv・得意練習・数値欄・判定・基礎上限）は中身の幅だけ取る。Lv は最大の「PSR50」、コツボナ・試合経験点などは最大3桁の幅で十分。余った幅は備考欄へ回す。
- 名前・見出しの折り返し位置は <wbr> ではなくゼロ幅スペース（\u200b）で入れる（<wbr> だと PC でも折り返してしまうため）。

**備考欄（メイン・サポート両方の表の一番右。deck.js の NOTE_RULES で自動表示）**
- サポートデッキの表には「守備（ポジション）」欄は置かない（一致・不一致・回復の判定と意味が被るため）。
- 練習改革：そのLvで改革を持っているキャラに「〇〇改革」。複数人いても全員。投手デッキはコン改革・スタ改革だけ、野手デッキは筋力改革・走塁改革だけ表示（chars.json の bonus「〇〇練習改革(…)」で判定）。メイン・サポート両方。
- 経験点上限：サポートデッキで「サポ：獲得経験点上限」が一番高いキャラだけ、2行で「経験点上限／数値」。サポートのみ。
- アイテム追加：メイン表のみ。chars.json の「アイテム」（追加枠・キャラ持参アイテム）があるキャラに「※アイテム追加」。
- 当てはまらなければ空欄。ルールを増やすときは NOTE_RULES に関数を足す。

**追加アイテム（デッキ詳細の項目）**
- 持ち込むキャラ名をアイテム名の後ろに括弧で付ける：「万能パワドリンク(山本由伸)」。同じアイテムを複数人が持つときは「(○○、△△)」と全員書く。名前は表と同じ短い表記（カタカナ名は最初の「・」「=」の手前まで。deck.js の shortName）。

**デッキのデータ（decks.js）**
- 無課金アカウントで育成したデッキには `f2p:true` を付ける。育成結果画像の右に「無課金」タグが出て、絞り込みの「無課金のみ」で表示できる。
- 並び順の初期設定は「選手ランクが高い順」（同じランクは総経験点が高い順）。選択肢は上から ランク順・総経験点順・育成日が新しい順。
- 各デッキに育成日（更新日）を `date:"2026-10-04"` の形で必ず書く。解説動画の下に表示され、並び順「育成日が新しい順」に使う。
- 育成のポイントは `tips`（箇条書き）、動画は `video`（YouTubeのID。動画が無いデッキは `video:"なし"` で「なし」と表示）。動画に注記が必要なときは `videoNote`（「※」は自動で付く）。
- 高校キャラ（chars.json の「所属高校」がそのシナリオの学校）には名前の後ろに●が付く。ロマン開花學園はメイン・サポート両方、アンドロメダ学園はメインだけ（deck.js の SCHOOL_MARK）。
- キャラ検索は、名前・読み仮名・二つ名の読み仮名のどれでも一致する（chars.json の「読み」「二つ名読み」）。
- 公開用リポジトリでは、コミット作者を noreply にし、コミット文・PR・サイトに本名や呼び名を書かない（公開名は「りょーつー」）。

## 全ページ共通：スマホとPCの両方で崩れないこと（今後追加するページ全部）
管理人の指示（2026-11-04）。新しいページや表示を足したら、**公開する前に、幅320px・375px・1100pxの3つで見た目を確認する**（320px＝iOS15対応で最も狭いiPhone SE第1世代、375px＝管理人のスマホ、1100px＝PCの広い画面）。
- 文字が1文字だけ折り返す（例：「こちら」の「ら」だけ次の行）、表がはみ出す、文字が欄からはみ出す、余白が広すぎて間延びする、のどれも起きないようにする。
- 直し方の目安：スマホでは文字サイズを幅に合わせて小さくする（`clamp(12px, 3.6vw, 16px)` など）、折り返す場所は意味の切れ目（キャラ名の後など）にする（`display:inline-block` の `span` で区切る）、表は列の幅に上限を付ける（`max-width`）、横に長いものは `overflow-x:auto` の枠に入れる。
- 確認のしかた：ブラウザ（Playwright）で幅320px・375px・1100pxのスクリーンショットを撮って見る。320pxだけを直すときは、幅320px以下のときだけ効く指定（`@media (max-width:340px)`）か、表の枠の中の横スクロールで直し、375pxの見た目を変えない（直す前後の375px・1100pxを撮って比べる）。

## 全ページ共通：ダークモードでも白背景のまま（管理人の指示 2026-11-04）
- スマホをダークモードにしても、サイトの背景は白（ライト）のままにする。背景が暗いと青文字が見づらいため。
- 実装：`src/layout.html` に `<meta name="color-scheme" content="light">`、`src/assets/style.css` の `:root` に `color-scheme:light`。`@media (prefers-color-scheme: dark)` の指定は入れない（入れたら消す）。
- 例外：Tier表メーカー（`/tier/`）は最初から黒背景のツールなのでそのまま。
- 単独ページ（契約書シミュレータなど、pawa-data 側のテンプレートから作るページ）にも同じ指定を入れる。

## サクセス デッキ組み方（`src/pages/deckbuild-roman.html` / `deckbuild-andromeda.html`）
- トップの「サクセス デッキ組み方」（デッキまとめの下、見出しのマーカーはオレンジ `mk orange`）から、学園ごとのページへ。
- 内容がまだ無い部分は `<p class="wip"><b>準備中です。</b>…</p>` の表示。本文を書いたらこの行を置き換える。
- ページ先頭の `noindex: yes` で検索・サイトマップから外している（中身が薄いページをAdSense審査に見せないため）。**本文が入ったら `noindex: yes` の行を消す**とサイトマップにも入る。
- トップのカードは準備中の間は `scard soon`（薄い表示）。本文が入ったら `soon` を外し、説明文の「（準備中）」を消す。
- ギミック・立ち回り・イベント選択肢の「攻略まとめ」ページは作らないことにした（別の項目にする予定）。

## キャラページ（/chars/）：URLは /chars/ページ番号4桁/、一覧は /chars/
`charpages.py` が `chars.json` から作る（`build.py` が呼ぶ）。
- `src/chars/config.json` … 「重要ボーナス」の項目と並び順、公開するキャラ
- `src/chars/texts/*.json` … 管理人が書く評価・イベント・自己紹介。「評価」を書いたら「評価記入日」（例 "2026/11/11"、管理人から文章をもらった日）も書く。評価欄に【記入日…】と出る（2026-11-11 管理人指示。既存18人は入力した日を記録から入れた）
- キャラの種別（野手用／投手用／兼用）は、得意練習（メイン・サブ）で決める（`src/chars/config.json`「種別の判定」。投手の練習だけ＝投手用、野手の練習だけ＝野手用、両方＝兼用。得意練習のデータが無いキャラだけ、従来のボーナス条件→金特で決める）。野手用は【野手】を上、投手用は【投手】を上に出す。兼用は、メインポジションが投手なら【投手】が上、投手以外なら【野手】が上（得意練習のデータが無いキャラだけ、管理人に聞いて「兼用の並び順」に書く）
- `src/ranking/ranking.json` … イベキャラランキング（Tier表。SS・S・A・B、使う時だけC）。管理人が書く（キャラ名・ランク・理由・評価日）。ここに書くと、ランキングページ（/ranking/roman/ ・ /ranking/andromeda/）のTier表と、そのキャラページの評価欄（ランク・ランキングへのリンク・【評価日】）に自動で出る。**キャラごとの評価文章は、ランキングページには出さず、各キャラの `src/chars/texts/<名前>.json` の「評価」（文章のリスト）にだけ書く**（キャラページの評価欄に、ランクの下に出る）。「公開」を true にするまでは noindex。キャラは「公開するキャラ」にいる必要がある。新しいランキングを足す時は、トップや各ページからのリンクも決める。任意の項目：「上の解説欄」（Tier表の上。X のポストURLだけの行は埋め込み表示）、「動画」（YouTubeの動画ID）、「ボーナス表」（前後・基礎合計・コツボナ・推奨Lv）、「キャラページに出さない」
  - トップ（`src/pages/home.html`）のランキングカードの評価日は `{{rk_date_roman}}` `{{rk_date_andromeda}}` と書くと、ranking.json の「評価日」が自動で入る（ランキングの評価日を変えればトップも変わる）。新しいランキングは `{{rk_date_<キー>}}`。
  - 「種別」（投手／野手）で目印が変わる：投手＝☆至高金特（至高のスターター等）・★オリスト・★オリ変、野手＝☆至高金特（球界の頭脳・至高の〇〇手）のみ。
  - 文章（解説欄・理由）の中で `{青:文字}` `{赤:文字}` `{太:文字}` `{青太:文字}` `{赤太:文字}` と書くと、その部分が青／赤／太字／青太字／赤太字になる（青は #1565c0、赤は #c62828）。
- `src/chars/skill_kinds.json` … 特殊能力の種類（青・金・赤・緑・虹）。pawa-data の `event-chars/特殊能力/skills.json` から作った写し。skills.json を更新したら作り直す（手動）
- **新キャラを足したら、トップの「最新情報」欄も更新する**：`src/pages/home.html` の `<ul class="news">` に1行足す（`<li><a href="{{root}}chars/ページ番号4桁/">○○のデータ・イベントはこちら</a></li>`）。赤文字は CSS（`.news a`）で付く。新しい順に上へ足し、古いものは管理人と相談して外す。キャラページが noindex でもリンクは貼る。足したら `python3 build.py <chars.json>` でビルドし直してPR。
- デッキを `decks.js` に足してサイトをビルドし直すと、使用デッキ例も自動で更新される

## URLの付け方（2026-11-12 りょーつー指示）
- サイトのURLに「-」は使わない。区切りは「_」で統一する（例：`guide/limit_break/`）。「-」と「_」の見分けが付きにくいため。
- 公開済みページのURLを変えるときは、`build.py` の `REDIRECTS` に「古いURL → 新しいURL」を足す（古いURLに、自動で新しいURLへ移動するページが作られる）。

## ガチャ記事を足すとき（/gacha/<id>/、2026-11-12〜）
管理人がガチャのお知らせ・提供割合のURLを送る → それを元に記事＋シミュレータのページを作る。
1. `src/gacha/<id>.json` を作る（id は「開始日_キャラ」例 `2026_1111_shampoo`。「-」は使わない）。中身は既存の json を手本に、**公式ページの表示どおりの数字だけ**を入れる（推測しない。分からない点は管理人に聞く）。
   - `steps`：ステップごとの連数・石・枠。枠の `target` は「目当てキャラのみの枠」なら `only`、そうでなければ `share`（そのレアリティが出たとき `share` の割合で目当てキャラ）。
   - `extra`：ガチャ以外で手に入る目当てキャラ（イベント報酬など）。例 `[{"rarity": "PR", "n": 1, "label": "イベント報酬"}]`。ガチャと同じバージョンのものだけ入れる（別バージョンは今の計算では扱えない）。無ければ書かない。
   - `comment`：「管理人の評価」の文章（1段落ずつのリスト。{太:…} {赤:…} などの色指定はキャラページと同じ）。`comment_date` に記入日（例 `2026/11/12`）。シミュレータの前に出る。イベキャラとしての評価（ランキングでのランクだけ。評価文は載せない）があれば自動で一緒に出る。
2. `python3 gacha_calc/build_tables.py` を実行（数十秒）。周回ごとの確率（SR・PSRが引ける確率／Lv40／SR Lv45／PSR Lv50）を `src/gacha/<id>.tables.json`（博士像なし）と `src/assets/gacha_t/<id>.bin`（博士像あり・全組み合わせ）に書く。
   - PSR目標の「手持ち→完成確率」の表（博士像つき）はガチャによらず共通で、計算に約1時間半かかる。`gacha_calc/cache/`（gitに入れない）か `/mnt/project-files/gacha-calc/` に保存したものを使い回す。どちらにも無いときだけ自動で計算し直す（ディスク空き約16GB必要）。
   - `src/assets/gacha_v/`（「引いてみる」用の表・727ファイル）も毎回同じ内容で書き直される。ルールを変えない限り差分は出ない。
3. `python3 build.py` → トップの「ガチャ」欄にカードが自動で出る（新しい順）。
- 計算は「引き終わってから、手持ちの目当てキャラを一番成功率が高い順番で合成」（全パターン）。記事の「計算のしかた（注意）」は毎回自動で入る。
- ダイジョーブ博士像（PSR像・SR像は0〜5枚、PR像・R像は0〜10枚）は「同じレアリティのカードを100%で+1」として計算。ページ上で枚数を選ぶと表とシミュレータが変わる。合成ルールや像の上限枚数を変えるときは `gacha_calc/vtable.c`・`build_tables.py`（`KS`・`KL`）・`src/assets/gacha.js` を直し、キャッシュを消して計算し直す。
- 表の「100%」は、失敗する可能性のある手持ちが1つも残らないとき（例：確定枠で必ずそろう）だけ。計算の誤差で1に見えても失敗の可能性が残っていれば「ほぼ100%」と出す（`build_tables.py` の `fails`）。
- 今の計算は「ガチャに出る目当てキャラが1バージョンだけ」のガチャ用。別バージョンが同じガチャに出る・目標がLv40/SR Lv45/PSR Lv50以外、などは計算を足す必要がある。
