# 旧バージョンつきの計算の検算（2026-11-12）

ページで動く計算（`src/assets/gacha_old.js`＋`gacha_calc/old.c`）は「旧カードを先に使う」方式で、合成の順番を全部は調べていない。
どれくらい低く出るかを、時間のかかる別の計算と比べたときの道具と結果。

- `exact.py`：手持ち全部（新・旧）をどの順番でも合成できるとして最大の確率を出す（カード8枚くらいまで）。
- `ref.c`＋`gen_pool.py`：今までの計算（vtable.c と同じ前提）に「旧カードをいつでも・どこにでも合成できる」手を足した計算。
  `python3 gen_pool.py '[[3,4]]' 3 24 34 60 && gcc -O2 -o ref ref.c && ./ref ref.f32`（[[ランク 0=R..3=PSR, +いくつ],…]、3=PSR目標・2=SR目標）。
  PSR目標は旧カード1枚で約1分半・メモリ約1GB、2枚以上は現実的でない（だからページでは使えない）。旧カードなしなら今までの表と一致することを確認済み。
- `run_node.js`：ページと同じ計算を Node で動かす。
- `tablecmp.py`・`tablecmp2.py`：周回ごとの確率にして比べる（作業用。表の置き場所は書き換えて使う）。

## 結果（シャンプーのガチャ、博士像なし、周回ごとの確率の差がいちばん大きい周）
| 旧カード | 目標 | ページの計算 | 検算 | 差 |
|---|---|---|---|---|
| PSR+4 1枚 | PSR Lv50（6周） | 67.3% | 67.7% | 0.4 |
| SR+4 1枚 | SR Lv45（2周） | 74.7% | 75.5% | 0.8 |
| SR+4 1枚 | Lv40（1周） | 74.5% | 74.9% | 0.3 |
| PR+2 1枚 | SR Lv45（3周） | 92.35% | 92.43% | 0.1 |
| R+5・R+3 | SR Lv45（2周） | 42.8% | 42.9% | 0.1 |

- 「あと1段階で+5になる旧カード」（+5素材は75%で+3）がいちばん差が出やすい。
- 旧カード2枚以上の組み合わせは、検算側が重すぎて周回ごとの表では比べられていない（小さい手持ちでの exact.py との比較だけ）。
- 手持ち1つ1つで見ると、めずらしい手持ち（例：SR1枚・PR16枚・R24枚）では10ポイントほど低く出ることがある。
